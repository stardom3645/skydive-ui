# 연결 관계 강조 조사·탐색 규칙

검토일: 2026-10-26. 실제 수집 그래프 835개 객체, 1,777개 간선과 활성 수동 매핑 2건을 조사했다. 수동 매핑의 명시된 포트·스위치 소속과 포트·NIC 연결을 포함한 UI 관계 그래프는 837개 객체다. 원본 그래프·API·수집기는 수정하지 않는다.

## 기존 구현에서 확인한 문제

- `App.addEdge`는 `ownership`/`vownership`을 `Node.parent`로 옮기며, Kubernetes 상세 전용·ReplicaSet·Pod/PVC 관계를 렌더링 링크에서 제외한다. 기존 강조는 렌더링용 링크와 계층선만 보므로 원본 관계가 누락된다.
- `connectionFocus`는 SVG의 y좌표를 상하 관계로 사용한다. 같은 y좌표의 연결은 재귀 탐색에서 빠지고, 화면 배치/접힘에 따라 범위가 바뀐다. 서로 다른 종류의 Kubernetes 참조와 네트워크 간선도 같은 방식으로 처리한다.
- CCVM 원본에는 호스트→CCVM 소유, CCVM→vNIC 가상 소유, vNIC→CCVM 가상 네트워크 관계가 있다. 화면에서 CCVM·NIC만 보이는 것은 다른 수집 관계가 없다는 뜻이 아니다.
- 화면의 공통 부모/그룹을 관계의 중간 노드로 쓰면, 관계 없는 형제 VM·Pod·서비스가 연결된 것처럼 강조될 수 있다.

## 모드별 계약

**직접 연결(기본)**: 원본 객체 ID를 기준으로 실제 수집 간선 또는 활성 수동 매핑의 명시적 관계로 연결된 1단계 이웃만 포함한다. `Node.parent`, 이름·IP·MAC·좌표가 같다는 이유로 간선을 만들지 않는다. Deployment→ReplicaSet→Pod의 시각적 단축선은 1-Hop 간선이 아니다.

**전체 연결**: 직접 관계에서 시작해 아래 규칙으로만 확장한다. 화면 좌표·배치 부모·그룹은 탐색하지 않는다. 이 모드는 관계 탐색이며 통신 가능성, 실제 패킷 경로 또는 장애 전파를 판정하지 않는다.

| 관계/객체 범위 | 전체 연결 확장 | 중단·격리 기준 |
|---|---|---|
| Host, VM/시스템 VM/라우터 (`libvirt`), NIC, Bridge, Bond, VLAN, OVS, 가상 NIC | 소유 관계의 방향과 인터페이스 역할을 사용한다. 네트워크 상향/하향 탐색은 중간에 반대 방향으로 전환하지 않는다. | VM에서 도달한 Host가 다른 VM/NIC로, NIC에서 도달한 상위 스위치가 다른 포트로 다시 퍼지지 않는다. |
| `layer2`, `vlayer2`, 활성 수동 매핑, patch/veth/tunnel/mapping | 수집된 해당 간선만 사용한다. Bridge의 VLAN 인접 관계로 역할을 구분하고, 직접 NIC 연결도 지원한다. | 알 수 없는 객체/관계는 1-Hop까지만 포함한다. 만료 LLDP·삭제된 간선은 제외한다. |
| SR-IOV `vf` | PF→VF는 하향, VF→PF는 상향이다. | 같은 device 타입이라는 이유로 PF를 경유해 형제 VF로 확장하지 않는다. |
| 스위치→포트 소속 | 수집 ownership, 또는 활성 수동 매핑에 명시된 스위치/포트 소속만 사용한다. | 임의의 표시 부모는 사용하지 않는다. 수동 매핑 비활성/삭제/AUTO 전환으로 가상 포트가 제거되면 강조 관계도 제거된다. |
| Kubernetes Cluster, Namespace | 선택된 Cluster/Namespace는 실제 소유 하위 자원을 확장한다. 다른 객체에서 도달한 부모는 상향으로만 진행한다. | 공통 Namespace/Cluster를 경유한 형제 워크로드 확장을 금지한다. 명시적 클러스터 식별자가 충돌하는 간선은 격리한다. |
| Deployment→ReplicaSet→Pod, DaemonSet/StatefulSet/Job/ReplicationController→Pod, CronJob→Job | 확인된 방향으로 하위 실행 객체 또는 상위 소유 체인을 따라간다. | 상향으로 도달한 컨트롤러에서 형제 Pod로 내려가지 않는다. 실제 중간 객체/간선이 빠졌으면 이름으로 보완하지 않는다. |
| Node→Pod 스케줄링, Host↔K8s Node, PV↔Node, K8s Container↔런타임 | Node 자체를 선택한 경우에만 자신의 실제 스케줄된 Pod를 확장한다. 그 외에는 연결 상대를 확인하고 멈춘다. | Pod에서 Node를 거쳐 다른 Pod로, K8s Node에서 Host를 거쳐 다른 VM으로 확장하지 않는다. |
| Ingress→Service→Pod/Endpoints/EndpointSlice | 선택한 자원의 정방향 참조를 따라간다. 역방향 참조는 상위 참조자만 따라간다. | Pod에서 도달한 Service를 거쳐 다른 backend Pod로 확장하지 않는다. selector 관계를 실제 통신 연결로 설명하지 않는다. |
| Pod→PVC→PV, StorageClass→PVC/PV, ConfigMap/Secret/ServiceAccount 참조 | 정방향 참조를 확장한다. 선택된 공유 객체는 자신의 실제 참조자도 확인한다. | 도달한 공유 PVC/ConfigMap/Secret에서 다른 소비자로 역확장하지 않는다. Released/Failed/Lost 및 명시적 UID/volumeName 충돌 바인딩은 제외한다. |
| NetworkPolicy, HPA, PDB | 확인된 관계 유형/끝점 조합에 한해 참조로 처리한다. | 정책의 적용 관계는 통신 허용·실제 트래픽·장애 전파를 의미하지 않는다. |
| 기타 Infrastructure/K8s 객체 | 실제 간선의 직접 이웃과 명시적 소유 관계를 보존한다. | 미분류 간선의 재귀 탐색은 금지한다. 수집되지 않은 관계를 추정하지 않는다. |

## 화면·수명·성능

- 원본 간선은 렌더링 필터 적용 **이전**에 별도 인덱스에 보존한다. 실제 간선 ID로 추가·수정·삭제하며, 스냅샷 재동기화와 객체 삭제에서도 함께 갱신한다.
- 강조 결과만 화면의 실재 객체/접힌 자기 그룹으로 투영한다. 숨긴 Service를 Namespace 등 조상 카드로 바꾸지 않는다. 접힌 그룹의 강조는 관련 구성원 존재를 뜻하며 그룹 전체의 관계가 아니다. 관련 자원 수와 숨겨진 자원 수는 별도로 안내한다.
- 숨겨진 트래픽 선은 새로 표시하지 않는다. 소유 계층선은 실제 소유 간선이 있을 때만 선택한다. 컨트롤러→Pod 표시 단축선은 전체 모드에서만 실제 선택 체인을 요약할 수 있다.
- 기본 `직접 연결`, Segmented로 `전체 연결` 전환, 선택 변경 시 동일 모드로 재계산, ESC/해제로 강조 CSS를 해제한다. 모드 전환은 위치·접힘·줌·상태 색상을 바꾸지 않는다. 상세 화면에서 호출하는 기존 자원 찾기/중앙 이동 동작은 유지한다.
- 0개 관계는 `수집된 관계 없음`이다. 수집 실패/지연 메타데이터가 있으면 `수집/관계 미확인`으로 구분한다. 어느 경우도 물리적으로 연결이 없다는 단정이 아니다.
- 인접 인덱스 구축은 O(V+E)이며 간선/객체 변경 시 무효화한다. 탐색은 반복 큐와 `(객체, 방향 상태)` 방문 집합을 사용한다. 500개 객체·10,000회 간선 검사·32단계 한도에 도달하면 `일부`로 명시한다.

CCVM: 직접 연결은 호스트·vNIC 2개이며, 전체 연결은 vNIC·호스트·bridge0·물리 NIC·활성 수동 포트·상위 스위치 6개다. 다른 VM, VLAN, 형제 NIC와 다른 포트는 포함하지 않는다. 해당 시점에 유효한 수동 매핑과 수집 간선만 사용한 결과이며 고정된 경로/수치를 UI에 넣지 않는다.

해당 스냅샷 전체 객체의 두 모드 계산(약 1,674회)은 로컬 감사 실행에서 약 38ms, 가장 큰 단일 탐색은 약 2,110회 간선 검사였다. 렌더링이나 네트워크 시간을 포함한 성능 보장은 아니다.

## 검증의 한계와 기존 실패

- 실제 데이터에 없는 유형과 대규모/순환/누락 수집/바인딩 충돌은 고립된 테스트 그래프로 확인한다. 없는 관계를 만들어 운영 데이터에서 검증한 것으로 보고하지 않는다.
- 확대 실행한 `KubernetesRelationshipIntegrity.test.ts`의 집계 표시 2건은 `관계 미확인` 대신 `-`가 나오는 기존 실패다. 변경 전 HEAD 소스를 별도 임시 디렉터리에서 실행해 같은 두 실패를 확인했다. 본 변경은 상태 판정/집계 표시를 바꾸지 않는다.
- 기존 컨텍스트 메뉴 테스트의 오래된 `표시 옵션`/`다운된 노드 숨기기` 문자열은 이미 운영 코드에 있는 `보기 설정`/`다운된 객체 숨김`으로 맞췄다. 해당 UI 자체는 변경하지 않았다.

## 실제 화면·최종 검증 결과

- CCVM: 기본 직접 연결 2개(호스트·vNIC), 전체 연결 6개를 실제 화면에서 확인했다. 모드 전환 전후 모든 렌더링 객체의 transform이 동일했다. ESC 해제 후 강조/흐림 클래스가 모두 0개이며 객체 위치가 유지됐다.
- Kubernetes `calico-node-2cpn2`: 직접 연결 3개(네임스페이스·DaemonSet·배치 Node), 전체 연결 4개(상위 Cluster 추가)를 확인했다. 같은 DaemonSet의 형제 Pod와 다른 워크로드는 흐림 상태를 유지했다. 모드 전환 전후 객체 위치가 동일했다.
- 강조 중 배치 Node로 선택을 바꾸자 전체 모드를 유지하면서 관련 42개로 즉시 갱신됐다. 직접 연결로 전환하면 11개였고, 해제 버튼으로 강조/흐림 클래스가 모두 제거되며 위치가 유지됐다. 이 수치는 검증 시점 실제 데이터이며 제품 코드에 하드코딩하지 않았다.
- 관계 엔진은 46개 지원 객체 종류의 직접 이웃 계약, 방향 전환 제한, 공유 자원, 바인딩 충돌, 수동 매핑, SR-IOV, 순환·검사/객체/깊이 한도를 테스트한다. 화면 통합 테스트는 숨김/접힘 투영, 원본 간선 보존, 갱신·삭제·재동기화, 모드·선택 변경과 해제 상태를 확인한다.
- TypeScript `tsc --noEmit` 통과. 관계·모드·컨텍스트 메뉴·문제 강조 상태·Mold 네트워크 강조·Kubernetes 계층·수동 포트 매핑·보류 간선 관련 테스트 **133개 통과**.
- 프로덕션 빌드 통과. 기존 `d3-flextree` version export와 번들 크기 관련 경고 4개가 남는다. 빌드 출력은 임시 경로를 사용해 기존 작업 중인 dist 파일을 덮어쓰지 않았다. `git diff --check` 통과.
