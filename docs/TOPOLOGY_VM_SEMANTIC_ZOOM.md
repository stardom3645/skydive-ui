# Infrastructure 사용자 VM Semantic Zoom

> 2026-10-27: 기본 토폴로지의 자동 전환과 이에 종속된 카드 치수·레인 압축·Fit 재배치·연결선 가시성 변경을 롤백했다. 아래는 향후 재사용을 위해 보존한 구현 기록이다. 현재 `Topology`는 배율과 관계없이 기존 상세 카드를 사용하며 이 전환을 호출하지 않는다. 상세 내용과 전후 검증은 [롤백 기록](TOPOLOGY_SEMANTIC_ROLLBACK.md)을 참고한다.

Infrastructure의 일반 객체·그룹과 실제 사용자 VM(`libvirt`, 계층 7080, Kubernetes 제외)에 적용한다. 사용자 VM은 기존 전용 밀집 타일을 유지하며, 나머지 일반 객체는 공통 이름·상태 카드로 축소한다. 상태 판정, 메트릭 수집·해석, 관계 그래프의 탐색 의미, API와 운영 프로토콜·포트는 변경하지 않는다.

## 세 화면의 역할

| 모드 | 최초 전환 기준 | 역할 / 표시 | 장면 크기 |
| --- | --- | --- | --- |
| 상세 | 배율 표시 29% 이상 (반올림 포함) | 기존 카드 전체: 이름·상태·CPU·메모리·디스크 | 기존 크기 |
| 간략 | 100px 이상, 배율 표시 29% 미만 | 기존 가로형 카드: 이름·상태·CPU·메모리 | 480 × 200 |
| 밀집 | 100px 미만 | 전체 VM 상태 분포: VM당 상태 사각형 1개 | 80 × 80 |

밀집 타일에는 아이콘·텍스트·그림자가 없다. 기존 카드의 `model.status`를 그대로 사용하고, 실제 Ant Design 6 `Tag`의 `success / warning / error` 색상과 `outlined / solid / filled` 변형으로 표현한다. 정상은 옅은 outlined Tag, 주의·장애는 solid Tag, 미확인·비활성은 중립 Tag를 사용한다. SVG 역배율 보정을 통해 Ant 기본 1px 테두리·4px 모서리를 화면 픽셀로 유지한다. 타일의 외곽 크기와 연결선 좌표는 원래 장면 좌표를 유지한다.

타일 Hover는 기존 Ant Tooltip에 이름, 상태, CPU, 메모리, 수집 출처 및 상태 설명을 표시한다. 카드에 전달되는 동일한 측정값을 사용하며, 없는 사용량을 0으로 만들지 않는다. 클릭·더블 클릭·컨텍스트 메뉴는 기존 D3 객체 선택 및 상세 탐색 경로를 사용한다.

## 배치와 전환 안정성

밀집에서는 타일 사이와 행 사이를 16 장면 단위로 줄여 호스트별 최대 10열 그리드로 배치한다. Infrastructure 그룹 요약은 상세 모드에서 기존 카드를 유지하고, 간략에서는 400 × 220, 밀집에서는 320 × 200으로 바뀐다. VM 그룹 요약은 타일 그리드 왼쪽에 정렬한다. 그룹에는 이름, 직접 하위 수와 기존 상태 집계를 표시하며 별도의 상태 타일로 바꾸지 않는다. 펼쳐진 NIC 및 그룹은 소유 VM의 실제 배치 단위에 포함해 다른 타일과 겹치지 않게 한다. 그룹을 접으면 해당 타일이 숨겨지고 펼치면 원래 객체들로 복원된다.

판정 너비는 기존 VM 카드 너비 480에 실제 SVG 배율을 곱한 화면상 예상 너비다. 이미 축소한 타일 자체를 기준으로 삼아 확대해도 작은 타일에 갇히는 문제를 피하기 위해 세 모드가 같은 기준자를 사용한다. 상세는 줌 컨트롤과 같은 정수 반올림을 적용해 표시 29%부터 진입한다. 약 27.3% 미만에서 간략으로 돌아가도록 하향 여유 구간을 둔다. 밀집 경계는 기존 양방향 8px 여유 구간을 유지한다. 화면 맞춤의 간략 배율 상한은 실제 28.49%(표시 28%)로 제한한다. 이전 상한 34.79%가 표시 35%로 반올림되면서 간략으로 남던 문제를 방지한다. 줌 컨트롤도 원시 배율의 0.5% 변화량 대신 표시 정수 값과 버튼 활성 상태의 변화를 기준으로 갱신해, 반올림 경계의 표시 갱신이 누락되지 않게 한다.

휠 요청은 프레임당 합치고, 버튼의 확대·축소 애니메이션은 최종 배율에서 모드를 갱신한다. 같은 모드 안의 확대·축소는 전체 배치를 다시 계산하지 않는다. 전환 시 선택한 VM 또는 중앙에 가까운 VM의 화면 위치를 유지한다. 밀집의 카드 재배치는 즉시 적용하고, 화면 맞춤은 변경된 장면을 다시 측정하되 모드와 Fit 사이의 반복 전환을 방지한다.

## 연결선과 관계 범위

- 상세는 기존 연결선과 트래픽 동작을 유지한다.
- 간략은 기존 연결선 가시성 설정을 유지하고, 객체·연결 Hover 또는 선택 시 실제 측정 라벨을 표시한다.
- 밀집은 연결선·라벨·연결선 hit area를 기본적으로 숨긴다. 객체를 선택하면 해당 객체와 그 NIC의 실제 연결만 표시한다. 미수집 연결은 선만 표시하고 수치를 생성하지 않는다.
- 명시적인 `직접 연결 / 전체 연결` 탐색이 활성화되면 기존 관계 그래프가 반환한 `relationLinkIDs`가 표시 범위를 결정한다. 이전 선택이나 All 모드의 선이 Direct로 새어 나오지 않는다.
- 밀집에서 숨겨진 선도 관계 탐색의 후보로 유지한다. 표시 여부를 다시 탐색 조건으로 사용하지 않으며, 기존 숨김 태그와 만료 정책은 지킨다. `EventBased`에서도 All 범위를 정상 투영한다.
- 수집된 실제 소유 관계에 대응하는 기존 구조적 경로는 관계 탐색 시에만 점선으로 표시한다. 레이아웃용 부모·spacer를 실제 연결로 생성하지 않고, 구조적 경로에는 트래픽 라벨을 붙이지 않는다.
- 표시된 측정 라벨은 최소 12px 화면 글자 크기를 확보하고 충돌을 피한다. 원래 NIC별 측정 소스와 툴팁을 유지하며 값을 합산하지 않는다.
- 밀집에서는 트래픽 애니메이션과 장식용 사각 끝점 마커를 제거한다. 실제 방향 화살표는 유지한다.

경로는 기존 카드 경계·장애물 라우터가 실제 크기와 위치로 계산한다. 숨긴 경로도 준비해 선택 시 전체 트리를 재배치하지 않고 표시한다. 밀집 경로의 좌표는 가시성 갱신이 취소할 수 없게 먼저 적용한다. 브리지 경로는 이미 장애물 검사를 통과한 경로를 유지해 불필요한 곡선 대안 탐색을 줄인다.

## Infrastructure 전체 공간과 공통 그룹 UI

사용자 VM 외에 NIC, VLAN, 가상 브리지, 라우터 등 Infrastructure 그룹을 같은 Semantic Zoom 표현에 포함한다. Kubernetes 카드와 레인에는 이 변경을 적용하지 않는다. VM이 모두 접힌 상태에서도 그룹만 독립적으로 전환한다. 연결선 표시에는 기존 `vmSemanticMode()`와 관계 범위 경로를 재사용한다. 일반 객체 확장 후에는 일반 객체만 있는 Infrastructure에서도 같은 단계별 표시 정책을 적용한다.

원인은 고정 `NodeWrapper.size[1]`(440), 카드보다 넓은 이전 슬롯, 빈 공간을 줄이지 못하는 충돌 전용 양수 레인 보정이었다. 간략·밀집에서는 카드 너비에 각각 24·16 장면 단위의 슬롯 여백을 더하고, 실제 카드·Badge 경계의 점유 레인을 다시 정렬한다. 일반 레인 간격은 각각 96·64이며, 호스트 캡션 여유는 간략 192, 밀집 64로 줄이고 상세에서 기존 384를 유지한다. 밀집의 중복 프레임 캡션은 숨긴다. 실제 펼쳐진 VM/NIC/중간 proxy는 같은 소유 블록으로 이동한다. 밀집 타일 그리드 배치 후 레인을 한 번 더 압축하고 이후 실제 좌표로 기존 라우터가 연결선을 계산한다. 상세 모드의 기존 간격은 유지한다.

모드별 치수와 기존 장면 캐시를 사용하므로 연속 배율, 메트릭, Hover, 선택이 매 프레임 새 배치를 만들지 않는다. 같은 밀집 구간에서는 좌표와 배치 호출 수가 그대로 유지된다. 축소된 그룹은 기존 `TopologyTypeIcon`, `TopologyGroupHeaderSummary`, 링크 동작 상태 요약과 Tooltip을 재사용한다. 전체 자원 수와 직접 하위 수를 섞지 않으며 LLDP 발견 정보는 운영 상태 미수집으로 유지한다.

그룹 패널의 기존 행 토글·다중 표시, 파란 강조와 `상세` 이동 경로는 유지한다. `상세` 버튼의 전파 차단도 보존했다. 행의 Enter/Space는 같은 토글을 호출하고 자식 상세 버튼의 키 이벤트는 다시 토글하지 않는다. Infrastructure 패널만 공통 Detail/Ant 토큰으로 정돈해 검색·Down 필터를 한 줄에 배치하고 실제 IP가 있는 행 높이를 43px로 줄였다. 글자는 공통 본문 12px/보조 11px를 유지한다. 선택 배경과 파란 레일, Hover 배경, 키보드 포커스 외곽선은 별개다. 상태와 운영 상태의 판정 로직은 바꾸지 않았다.

검증에는 `InfrastructureSemanticLayout.test.ts`, `TopologyGroupSelection.test.ts`와 기존 Semantic Zoom·레이아웃·관계·선택·트래픽·Fit 테스트를 포함한다. 관련 181개 통과, 타입 검사 및 프로덕션 빌드 통과(기존 경고 4개). 전체 테스트는 1085개 통과, 기존 실패 26개가 남았으며 이전 실행 대비 새 실패는 없다. 기존 그룹 선택 테스트의 누락된 관계 포커스 의존성 스텁을 보완했다.

확장된 브라우저 장면은 2개 호스트의 NIC·VLAN·브리지 그룹과 30·60·100 VM을 포함한다. 같은 밀집 구간에서 배치 호출 0회와 좌표 변경 0건을 확인한다. 최종 결과는 `netdive-group-density-results.json`에 보관한다. 실제 서비스에서도 NIC·VLAN·가상 브리지·라우터·VM 그룹의 직접 하위 수, 축소 표현, 내용 잘림 없음, 두 행의 파란 강조 유지, 상세 이동, 검색, Down 필터 30/28개 전환 및 Enter 토글을 확인했다. Down 필터와 키보드로 임시 토글한 행은 검증 전 값으로 되돌렸다.

최종 확장 장면 78개 시나리오에서 카드 겹침·연결선 끝점 이탈·빈 경로·그룹의 가로/세로 내용 잘림·VM 타일 상태/외곽 불일치·관계 범위 누출 0건. 그룹만 남은 장면에서도 간략 그룹 8개 ↔ 상세 그룹 카드로 전환되며 상세 진입 후 축소 그룹 잔류 0개를 확인했다. 개발 빌드의 최초 모드 전환 시간은 장면 규모와 연결선 수에 따라 달라지며, 같은 밀집 구간에서는 세 규모 모두 배치 호출과 좌표 변경이 0이었다.

## 일반 객체까지 확장한 Semantic Zoom

일반 객체인 호스트·CCVM·SCVM·가상 라우터·NIC·VLAN·브리지·스위치도 같은 29% 상세 기준과 기존 히스테리시스를 사용한다. 객체 개수와 그룹 생성 여부를 전환 조건에 넣지 않는다. 따라서 단독 CCVM과 호스트만 있는 화면에서도 축소 표현이 동작한다. Kubernetes는 제외한다.

| 역할 | 상세 | 간략 | 밀집 |
| --- | --- | --- | --- |
| 사용자 VM | 기존 상세 카드 | 기존 CPU·메모리 가로 카드 | 기존 80 × 80 상태 타일 |
| 일반 객체 | 기존 상세 카드 | 공통 400 × 200 이름·상태·필수 정보 카드 | 공통 320 × 128 이름·상태 카드 |
| 그룹 | 기존 요약 카드 | 기존 공통 400 × 220 그룹 요약 | 기존 공통 320 × 200 그룹 요약 |

일반 객체는 `TopologyObjectStatusBadge`와 기존 이름 Tooltip을 재사용한다. 호스트의 VM 수, 네트워크 객체의 동작 Up/Down 또는 수집 네트워크명만 기존 모델에서 가져와 간략에 표시한다. CPU·메모리·디스크를 새로 해석하지 않는다. CCVM을 포함한 시스템 VM과 가상 라우터는 두 축소 단계 모두 이름과 상태만 표시한다. 상세 패널에는 기존 수집 정보가 그대로 남아 있다. 사용자 VM 타일의 형태와 상태 색상은 유지하고, Ant Tag의 기본 `all` 전환이 줌 보정 너비/transform을 별도로 보간하지 않도록 색상 속성만 전환한다. 최소 10%에서 SVG 외곽과 타일 좌표가 잠시 어긋나는 현상을 막는다.

일반 객체의 레이아웃 크기와 `foreignObject`, 배경, 실제 연결선 끝점은 같은 치수를 사용한다. 기존 점유 레인 압축과 VM/NIC 소유 블록은 유지한다. 축소 일반 객체가 그리지 않는 외부 상세 Badge 공간도 예약하지 않는다. 밀집에서는 호스트 카드의 이름과 중복되는 프레임 캡션을 숨겨 호스트 앞 간격도 64로 줄인다. 간략에서는 캡션에 192를 확보하고 상세에서는 기존 384를 유지한다. 모드 안의 연속 배율·선택·메트릭 업데이트로 슬롯을 다시 나누지 않는다.

기존 밀집 연결선/트래픽 정책을 일반 객체만 있는 Infrastructure 화면에도 동일하게 적용한다. 선택/직접 연결/전체 연결 범위 계산과 원래 관계·측정값은 바꾸지 않는다. 미수집 수치를 생성하지 않는다. 전환 시 선택한 일반 객체도 화면 앵커 후보로 사용한다.

카메라는 열린 상세 패널의 실제 경계와 12px 여백을 제외한 너비를 사용한다. Fit과 객체 중앙 이동, 모드 전환 시 중앙 앵커 선택에만 적용하며, 배치 엔진의 viewport 입력은 바꾸지 않아 패널을 여는 것만으로 VM 행을 다시 나누지 않는다. 닫힌 패널이나 그래프와 겹치지 않는 패널은 너비를 예약하지 않는다. 닫힘 전환 중 너비가 아직 남아 있어도 visibility가 hidden인 패널은 즉시 제외한다.

검증: 관련 194개 테스트, 타입 검사, 프로덕션 빌드 통과(기존 경고 4개). 전체 테스트 1098개 통과·기존 실패 26개이며 새 실패는 없다. 30·60·100 VM과 일반 객체/그룹을 섞은 장면, 단독 CCVM, 최소 10%, 패널 열린 Fit을 포함한 88개 브라우저 시나리오에서 객체 겹침, 빈 연결 경로/끝점 이탈, 그룹·일반 카드 가로/세로 잘림, VM 타일 외곽/상태 불일치, 관계 범위 누출 0건을 확인했다. 세 규모 모두 같은 밀집 구간의 줌은 배치 호출 0회와 좌표 변경 0건이었다.

실제 서비스에서는 CCVM이 22% 밀집/26% 간략에서 이름·상태만 표시되고 29% 상세에서 기존 CPU·메모리·루트 디스크가 복원되는 것을 확인했다. CCVM 선택 시 카드 좌표는 변하지 않았고 기존 상세 패널이 열렸다. 패널 열린 Fit에서 실제 카드 오른쪽 경계 약 931px, 패널 시작 1154px로 가림 없이 배치되었다. 검증 결과는 `netdive-infrastructure-identities-results.json`에 보관한다.

참고 성능: 개발 빌드의 30 VM + 일반 객체/그룹(표시 객체 약 95개) 장면에서 최초 밀집 전환은 약 437ms였다. 범위를 넓힌 100 VM + 일반 객체/그룹(약 165개) 복합 장면은 약 2.14초로, 큰 장면의 최초 모드 변경 비용은 남아 있다. 같은 모드 내 줌은 세 규모 모두 재배치 0회였다. 대규모 가상화나 라우터 교체는 포함하지 않았다.
