# Infrastructure Semantic Zoom 선별 롤백 (2026-10-27)

## 범위와 조사 기준

이 채팅에서 처음 도입한 Semantic Zoom은 현재 작업 트리에 미커밋 변경으로 남아 있었다. 도입 전 `79c0d31`의 토폴로지 메서드와 현재 소스를 비교했다. 커밋 전체나 파일 전체를 되돌리지 않았다. 롤백 직전 소스는 별도로 동결해 동일한 측정 코드를 빌드했다.

줌 이벤트의 Semantic 전환 예약 → 화면 너비에 따른 모드 판정 → 카드/그룹 치수 변경 → 레인·그룹 재배치 → 연결선 재계산 및 카드 재렌더 경로가 있었다. Fit도 모드 전환 뒤 장면을 재측정하는 경로를 사용했다. 같은 대역 안에서는 계산을 줄였지만 대역을 넘으면 큰 장면 변경이 발생했다.

## 복원한 기본 동작

- 모든 배율에서 기존 상세 카드와 `topologyCardDimensions`를 사용한다. 줌·이동은 SVG 변환만 변경한다.
- 모드별 VM·일반 객체·그룹 크기와 레인 압축, 밀집 그리드 호출, 모드별 배치 캐시 키를 제거했다. 기존 VM 배치 최적화 옵션은 도입 전 구현을 그대로 사용한다.
- Fit은 기존 장면 경계와 전체 뷰포트를 측정한다. Semantic 대역별 배율 제한과 Fit 재배치 반복을 제거했다.
- 연결선 경계 좌표·라우팅·라벨·Hover·애니메이션은 기존 상세 정책으로 복원했다. 미수집 트래픽 값을 생성하지 않는다.

총 25개 메서드를 도입 전 구현과 동일하게 복원했다. `connectionFocus`와 `applyTopologyNodeFocus`는 이후 추가된 관계 탐색 코드를 유지하면서 Semantic 조건만 제거했다.

## 유지한 기능과 보존한 코드

상세 패널·그룹 목록의 행/검색/필터 정돈, 파란 선택 상태, 다중 선택, 상세 이동, 상태 판정 및 메트릭·API는 롤백 직전과 동일하다. `직접 연결 / 전체 연결`의 실제 관계 그래프, 선택 대상 변경 시 강조 갱신, 관계 범위 컨트롤, 문제 탐색도 유지했다. 줌 비율의 반올림 표시 수정과 선택 테두리도 유지했다.

기본 화면에서 제거한 것은 자동 전환과 그에 종속된 표현 경로다. 향후 재사용을 위해 다음 코드를 보존했다.

- `InfrastructureVMSemanticZoom.ts`: 전환·치수 순수 함수
- `InfrastructureSemanticLayout.ts`: 축소 그룹/일반 객체 치수와 압축 유틸
- `InfrastructureCompactLayout.ts`의 `infrastructureDenseVMLayout`: 명시적으로 호출하는 밀집 배치 함수
- `TopologyNodeCard`의 명시적 Semantic props, 상태 타일·Tooltip 및 전용 CSS
- 라우터의 명시적 `smooth: false` 옵션과 순수 함수·명시적 렌더 테스트

현재 `Topology`는 Semantic props를 전달하거나 밀집 배치를 호출하지 않는다. 자동 전환 설정이나 새 UI 옵션은 추가하지 않았다. 보존된 구현 설명은 `TOPOLOGY_VM_SEMANTIC_ZOOM.md`에 기록으로 남겼다.

## 검증 방법

`tests/visual/TopologySemanticRollback.tsx`는 같은 결정적 그래프와 동작을 롤백 전 동결 소스와 롤백 후 소스에 실행한다. 각 환경은 동일한 production 설정으로 빌드한다. 30/60/100 사용자 VM에 호스트·시스템 VM·라우터·NIC·VLAN·브리지와 실제 개별 링크를 포함한다. 수집/API 호출 없이 동일 그래프 해시를 확인한다.

각 크기에서 2회씩 55%→34%→29%→25%→20%→15%→10%→22%→30%→55% 확대·축소, 같은 24프레임 이동, 같은 화면 맞춤을 실행한다. RAF 간격, Long Task, 트리 렌더 호출 및 CPU 시간을 기록한다. 빌드·테스트를 마친 뒤 같은 브라우저·뷰포트에서 전후를 순차 측정한다. 고정 대기 시간이 포함된 전체 소요 시간보다 트리 계산과 프레임 지연을 함께 본다.

각 배율과 선택·직접/전체 연결·그룹 접힘/펼침 뒤 카드 겹침, 연결선 끝점, 카드 치수 해시를 확인한다. 네트워크 지연이나 운영 환경의 모든 성능을 대표하는 결과는 아니다.

타입 검사 및 production 빌드는 통과했다. 관련 테스트는 250개 통과했다. 전체 테스트는 1,095개 통과, 롤백 전과 같은 기존 26개 실패다. 실패 범위는 기존 Kubernetes UI 계약, 데이터 정규화, 표시 설정 및 테스트 렌더 스텁 등이며 이번 변경으로 추가된 실패는 없다. Semantic 자동 전환만 검증하던 통합 테스트는 비활성 상태 검증으로 교체했고, 순수 함수·명시적 축소 렌더와 상세 패널 상호작용 검증은 유지했다.

실제 개발 서버는 롤백 코드를 반영했다. 검증 시 기존 백엔드 `http://10.10.1.97:8082`가 응답하지 않아 실데이터 화면은 비어 있었다. 백엔드 주소·프로토콜·포트·수집 로직은 변경하지 않았다.

## 전후 결과

같은 데이터 해시·1265×720 장면에서 각 크기와 동작을 2회 측정했다. 100 VM 줌 시나리오의 평균 소요 시간은 21.8초→6.2초(동일 고정 대기 포함), 트리 재계산 3회→0회, 트리 계산 시간 15.6초→0초였다. Fit의 추가 트리 계산은 1회→0회, 이동은 전후 모두 0회이며 약 467ms로 동일했다.

전후 각각 69개 시점(총 138회)에서 카드 겹침과 연결선 끝점 오류는 0건이었다. 롤백 후 모든 배율에서 상세 카드 치수가 일정하고 타일은 0개였다. 그룹 접힘/펼침, 목록 검색·여러 행 표시 선택·상세 이동·모두 펼치기를 확인했다. 직접→전체→직접 연결 전환도 원래 강조 범위로 복원됐다.

기존 최소 배율(수동 10%, 자동 28%)도 복원했다. 큰 그래프는 이 기존 제한 때문에 한 화면에 전부 들어오지 않을 수 있다. 원본 결과는 이 채팅의 산출물 디렉터리에 `netdive-rollback-before.json`, `netdive-rollback-after.json`, `netdive-rollback-comparison.json`으로 보존했다.
